6.3AI agents can now see your previews

Your previews are already tests.

Prefire turns every #Preview into a snapshot test, a Playbook screen and an image your AI agent can look at.

Write previews. Get the rest for free.

You already describe every state of a screen in #Preview. Prefire reuses them, so there is nothing extra to write or keep in sync.

#Preview("Trip") {
    TripView(status: .onTime)
        .previewUserStory(.trip)
}

#Preview("Trip delayed") {
    TripView(status: .delayed(minutes: 45, departure: "10:25"))
        .previewUserStory(.trip)
        .previewState(.delayed)
}

Snapshot tests, generated

The build plugin writes a test for each preview and compares it with the reference image on the devices you pick. A moved pixel fails CI, not the release.

Playbook

A catalog of every component and user story, inside your app.

Every state

Mark states with .previewState() and group screens into flows with .previewUserStory().

Let your agent see SwiftUI. Not guess it.

An agent that edits a view can't see the result. Prefire builds the app and returns the previews as images, right in the conversation.

One command to connect

claude mcp add prefire -- prefire mcp

Or the plugin with a skill: /plugin marketplace add BarredEwe/Prefire

prefire render writes PNGs with a JSON record for each preview. prefire board lays the last render out as an HTML flow board.

Set up in a minute. Pick one.

Swift Package Manager

Add the plugin to your snapshot test target.

.package(
  url: "https://github.com/BarredEwe/Prefire.git",
  from: "6.4.0"
)
.plugin(name: "PrefireTestsPlugin", package: "Prefire")

Xcode

Add the package, then the plugins in Build Phases.

// test target
PrefireTestsPlugin
// app target
PrefirePlaybookPlugin

Homebrew

The CLI for tests, render and the MCP server.

brew install barredewe/prefire/prefire
