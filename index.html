New in 6.3 · AI agents

Let your agent see SwiftUI.

An agent that edits a view can't see the result. Prefire builds the app and hands the previews back as images, on any iPhone or iPad, light or dark, without Xcode Previews.

You

Make the sign-in button bigger and check it in dark mode on iPhone and iPad.

Claude Code · prefire mcp
render_previews( previews: ["Sign in"], devices: ["iPhone 16 Pro", "iPad"], color_scheme: "dark" )
2 images rendered

The button fits on both devices. On iPad the form stretches too wide, so I capped it at 420 pt and rendered again.

list_previews

Every preview of the project with its file and line, so the agent knows what it can render.

render_previews

Builds the app and returns PNGs, on the devices, color scheme and Dynamic Type asked for.

build_board

An HTML board of the last render, grouped by user story, to review a whole flow at once.

Why not Xcode's own preview rendering?

  • No running Xcode, works from a terminal and in CI.
  • Many previews in one build, not one canvas at a time.
  • Real devices with their safe area, dark mode and Dynamic Type on request.
  • Built anew every time, so a stale canvas never shows old code.

Install

Choose how Prefire runs.

Use the plugin in Xcode or SwiftPM. Use the CLI for local and CI runs, and the MCP server for AI agents.

Xcode Build Tool Plugin

Add Prefire as a package dependency, then attach the test or Playbook plugin to the matching target.

Tests target  → PrefireTestsPlugin
App target    → PrefirePlaybookPlugin

Swift Package plugins

Add Prefire once, then attach plugins to the targets that should receive generated output.

.package(
  url: "https://github.com/BarredEwe/Prefire.git",
  from: "6.4.0"
)

.plugin(name: "PrefireTestsPlugin", package: "Prefire")

CLI

Install with Homebrew, then generate tests or Playbook models explicitly.

brew tap barredewe/prefire
brew install prefire

prefire tests
prefire playbook
prefire render "Sign in" --device iPad --color-scheme dark

MCP server

Install the CLI, add render_configuration to .prefire.yml, then connect the server from the project folder.

# Claude Code
claude mcp add prefire -- prefire mcp
# or the plugin, with a skill
/plugin marketplace add BarredEwe/Prefire
/plugin install prefire@prefire

# Codex
codex mcp add prefire -- prefire mcp

# VS Code
code --add-mcp '{"name":"prefire","command":"prefire","args":["mcp"]}'

Add to Cursor · AI guide

Need custom paths, devices or templates?

Add .prefire.yml when the defaults no longer match your project. Project-specific control stays in the config.

test_configuration:
  target: PrefireExample
  simulator_device: "iPhone15,2"
  required_os: 16

playbook_configuration:
  preview_default_enabled: true

render_configuration:
  scheme: PrefireExample
  test_target: PrefireExampleTests
